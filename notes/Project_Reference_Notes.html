Project Overview
1.1 System Summary

Movie Matcher AI is a content-based movie recommendation system developed as a final-year engineering project at Ahmedabad Institute of Technology (Team ID: 969101). The system allows users to select a movie title and instantly receive ten contextually similar movie recommendations, computed using TF-IDF vectorization and cosine similarity over a curated dataset of 10,000 movies.

The application is built on a Python Flask backend, uses two SQLite databases, and serves a rich multi-page frontend with interactive Chart.js dashboards. The underlying raw data originates from the TMDB (The Movie Database) open dataset comprising 1.17 million records.

Deployment: Local Flask development server running at http://127.0.0.1:5000. The application loads pre-trained pickle files at startup and processes all recommendation requests in-memory.

  • Full-dataset analytics dashboard built from 1.17M rows (chunked CSV reading)

ML Pipeline (End-to-End)

The recommendation system follows a classic content-based filtering pipeline. The pipeline is split into two phases: an offline training phase (runs once via train_model.py) and an online inference phase (runs live in app.py for every user request).

1
Data Collection — TMDB Dataset
The raw data source is TMDB_all_movies.csv (713 MB, 1,170,000+ rows, 28 columns). This CSV is first imported into movies_database.db by running csv_to_db.py once. The SQLite database then serves as the clean, queryable data source for model training.
2
Data Cleaning & Feature Engineering (train_model.py)
train_model.py reads all records from movies_database.db using pandas. The following transformations are applied:
  • Column selection: title, overview, genres, cast, director, poster_path, vote_average, vote_count, original_language, popularity
  • Null removal: dropna() on all required columns
  • Tag creation: A new tag column is created by concatenating: overview + genres + cast + director
  • Top-K selection: Sort by vote_count descending → take top 10,000 rows (most-voted = most data-rich)
3
TF-IDF Vectorization
The tag column for all 10,000 movies is fed into TfidfVectorizer from scikit-learn.
from sklearn.feature_extraction.text import TfidfVectorizer vectorizer = TfidfVectorizer( max_features=5000, # Keep top 5000 terms by corpus frequency stop_words='english' # Remove 318 common English stopwords ) vectorized_data = vectorizer.fit_transform(movies['tag']) # Output shape: (10000, 5000) — scipy CSR sparse matrix
4
Serialization with Pickle
Both the processed movies DataFrame (as a dict) and the TF-IDF matrix are serialized to disk using Python's pickle module. This allows app.py to load them instantly at startup without retraining.
import pickle # Save movies dictionary (used for title lookup, poster, metadata) with open('movies_dict.pkl', 'wb') as f: pickle.dump(movies.to_dict(), f) # → 19 MB # Save TF-IDF sparse matrix with open('vectorized_data.pkl', 'wb') as f: pickle.dump(vectorized_data, f) # → 7.4 MB
5
Flask Startup — Load PKL Files into Memory
When app.py starts (i.e., flask run), it loads both PKL files once into module-level variables. These remain in RAM for the entire session, making recommendation requests extremely fast (no disk I/O per request).
# app.py — executed once at module load time import pickle, pandas as pd with open('movies_dict.pkl', 'rb') as f: movies_dict = pickle.load(f) movies = pd.DataFrame(movies_dict) # DataFrame (10000, 10) with open('vectorized_data.pkl', 'rb') as f: vectorized_data = pickle.load(f) # CSR matrix (10000, 5000)
6
Recommendation Request — POST /recommend
When a user submits a movie title via the home-page search form, Flask's /recommend route executes the following logic:
from sklearn.metrics.pairwise import cosine_similarity def get_recommendations(movie_title): # Step 1: Find the row index of the selected movie idx = movies[movies['title'] == movie_title].index[0] # Step 2: Compute cosine similarity of this movie vs all 10K movies sim_scores = cosine_similarity( vectorized_data[idx], # shape: (1, 5000) vectorized_data # shape: (10000, 5000) ).flatten() # → (10000,) array of similarity scores # Step 3: Get indices of top 11 similar movies (sorted descending) top_indices = sim_scores.argsort()[-11:][::-1] # Step 4: Skip the movie itself (index 0 is always the query movie) recommendations = [movies.iloc[i] for i in top_indices if i != idx][:10] return recommendations
7
Render Results with TMDB Posters
The 10 recommended movies (with their metadata: title, overview, genres, poster_path, vote_average) are passed to the Jinja2 template. Poster images are fetched live from the TMDB CDN using the poster_path value: https://image.tmdb.org/t/p/w500{poster_path}.
Pipeline Summary: CSV (1.17M rows) → SQLite DB → Filter & Clean (10K rows) → TF-IDF Matrix (10K × 5K) → Serialize to PKL → Load in Flask → Cosine Similarity → Top 10 Results

TF-IDF Explained

TF-IDF (Term Frequency – Inverse Document Frequency) is a numerical statistic that reflects how important a word is to a document within a corpus. It is the foundational text representation technique used in Movie Matcher AI to convert each movie's textual tag into a numeric vector.

5.1 Term Frequency (TF)

Term Frequency measures how often a word appears in a single document (here, one movie's tag), normalized by the total number of words in that document.

Formula — Term Frequency
TF(t, d) = count(t in d) / total_words(d)

Example: If a movie's tag is "action hero saves world action" (5 words total), then TF("action") = 2/5 = 0.40

Intuition: A word that appears frequently in a movie's description is likely important for describing that movie. However, TF alone would give high scores to common English words like "the", "a", "is" — which is why we combine it with IDF.
5.2 Inverse Document Frequency (IDF)

IDF penalizes words that appear in many documents across the corpus (i.e., they are not distinctive). A word appearing in every movie tells us nothing about what makes that movie unique.

Formula — Inverse Document Frequency
IDF(t) = log( N / df(t) ) where: N = 10,000 (total movies in corpus) df(t) = number of movies containing term t

Example: If "crime" appears in 500 out of 10,000 movies → IDF("crime") = log(10000/500) = log(20) ≈ 2.996

Example: If "the" appears in 9,800 movies → IDF("the") = log(10000/9800) ≈ 0.020 (near zero → filtered out)

5.3 TF-IDF Score & Matrix Structure
Formula — Combined TF-IDF Score
TF-IDF(t, d) = TF(t, d) × IDF(t)

The result is a sparse matrix of shape (10,000 rows × 5,000 columns). Each row represents one movie; each column represents one of the 5,000 most-frequent terms (features) in the entire corpus.

Property Value Explanation
Matrix Shape (10,000 × 5,000) 10,000 movies × 5,000 vocabulary features
Value Range 0.0 – ~1.0 (float32) TF-IDF weight; 0.0 = term not in movie's tag
Storage Format scipy CSR sparse matrix Compressed Sparse Row — only non-zero values stored
Serialized Size 7.4 MB vs. ~200 MB if stored as a dense NumPy array
Sparsity Reason >99% zeros Most movies share <1% of the 5,000-word vocabulary
max_features 5,000 Only top 5,000 most-frequent corpus terms are kept
stop_words 'english' 318 English stopwords ("the", "a", "is", etc.) are removed
Why sparse? A movie about "space exploration" might use the words "astronaut", "orbit", "galaxy" — but will not use "romance", "bakery", "pirate" and thousands of other vocabulary terms. In a 5,000-word vocabulary, a typical movie tag only activates 30–80 non-zero columns. Storing zeros would waste ~200 MB; scipy's CSR format stores only the non-zero values with their row/column indices.
High vs. Low TF-IDF Scores
✅ High TF-IDF Score
  • Appears frequently in this movie's tag
  • Appears rarely across other movies' tags
  • Examples: unique actor names, niche genre words, rare locations
  • "zinedine" in a soccer movie's director tag
❌ Low / Zero TF-IDF Score
  • Stopwords ("the", "and", "a") → removed entirely
  • Very common genre words ("film", "story", "life") across many movies
  • Terms not in max_features top-5000 vocabulary
  • Terms absent from this movie's tag (majority of columns)

Cosine Similarity Explained

Cosine Similarity measures the angle between two vectors in a high-dimensional space. It is used to determine how similar two movies are, based on their TF-IDF feature vectors. Unlike Euclidean distance, cosine similarity is not affected by the magnitude (length) of vectors — only the direction matters. This makes it ideal for text comparison where documents of different lengths should still be comparable.

6.1 Formula
Formula — Cosine Similarity
cos(θ) = (A · B) / (‖A‖ × ‖B‖) where: A · B = dot product = Σ(Aᵢ × Bᵢ) for i = 1 to 5000 ‖A‖ = L2 norm (magnitude) of vector A = √(Σ Aᵢ²) ‖B‖ = L2 norm (magnitude) of vector B = √(Σ Bᵢ²)
Score Range Interpretation Example
1.0 Perfectly identical (same tag distribution) A movie compared to itself
0.6 – 0.9 Highly similar (strong thematic overlap) Two heist crime thriller movies with same director
0.3 – 0.6 Moderately similar (genre or cast overlap) Typical recommended movie pair
0.1 – 0.3 Loosely related (minor word overlap) Different genres, small cast crossover
0.0 No similarity (completely different vocabularies) A Korean art film vs. an English action blockbuster
6.2 Implementation in app.py
from sklearn.metrics.pairwise import cosine_similarity # vectorized_data: CSR matrix of shape (10000, 5000) # idx: integer row index of the query movie in the DataFrame sim_scores = cosine_similarity( vectorized_data[idx], # Query vector — shape: (1, 5000) vectorized_data # Full matrix — shape: (10000, 5000) ).flatten() # sim_scores — shape: (10000,) values in [0.0, 1.0] # argsort returns indices that would sort the array ascending # [-11:] gets the last 11 (highest) values # [::-1] reverses them to descending order top_indices = sim_scores.argsort()[-11:][::-1] # top_indices[0] is always the query movie itself (score = 1.0) # So we skip it and take indices [1:11] → 10 recommendations
6.3 Computational Cost Analysis
Performance: Computing cosine_similarity between a (1 × 5000) vector and a (10,000 × 5,000) matrix involves 10,000 dot products of 5,000-dimensional vectors. With scipy sparse matrices and NumPy's optimized BLAS routines, this runs in milliseconds on a standard laptop CPU. At 1 million movies, this approach would take ~100× longer and would require approximate nearest-neighbor methods (e.g., FAISS) for practical performance.

14.1 Core Formulas
TF-IDF
TF(t, d) = count(t in d) / len(d)
IDF(t) = log(N / df(t))
TF-IDF(t,d) = TF(t,d) × IDF(t)
Cosine Similarity
cos(θ) = (A · B) / (‖A‖ × ‖B‖)
Range: 0.0 (different) → 1.0 (identical)
Output shape: (1, 10000)

14.5 Complete Recommendation Execution Flow
①
User Input
User types or selects a movie name on the home page → browser submits POST request to /recommend with movie_title in form body.
②
Index Lookup
idx = movies[movies['title'] == movie_title].index[0] — Find the integer position of this movie in the 10K DataFrame.
③
Similarity Computation
cosine_similarity(vectorized_data[idx], vectorized_data).flatten() → Array of 10,000 similarity scores (0.0–1.0).
④
Ranking & Filtering
argsort()[-11:][::-1] → Top 11 indices by score (descending). Skip self (index 0 = query movie). Return top 10 remaining indices.
⑤
Template Render
Pass 10 movie records (title, overview, genres, vote_average, poster_path) to Jinja2 template → render recommendation cards with TMDB poster images.
📌 Key Insight: The entire recommendation engine requires zero database queries at inference time. All lookups happen against in-memory NumPy arrays and DataFrames loaded from pickle files at startup. This makes each recommendation response extremely fast (~10–50ms compute time on a standard CPU).
📚 Academic Context: This system is a classic implementation of content-based filtering using the Vector Space Model (VSM). The TF-IDF representation places each movie as a point in a 5,000-dimensional semantic space. Cosine similarity finds the nearest neighbors by angular distance. This approach, pioneered in information retrieval (Salton, 1975), remains highly effective for cold-start scenarios where user interaction data is unavailable.
